DESIGN ISSUES: Threat row 3's mitigation (the CLI hard stop after the grace period) assumes the watchdog thread can run. The watchdog is a Python thread, so it can't run during a C call that holds the GIL, and then neither the page timeout nor the hard stop fires. The design's ASCII85 contract says to size "after pdfminer's own stripping of `<~`, `~>` and whitespace". That stripping is two quadratic regexes that hold the GIL. A 1 MB ASCII85 content stream of whitespace hung the CLI with no stop (finding #1, reproduced and sampled). This problem existed before this slice, but it can't be fixed without changing what the design specifies. The architect should decide two things: whether the bounded ASCII85 filter may replace the regexes with a linear equivalent (proven against them by fuzzing, keeping INV-1); and whether threat row 3 should name GIL-holding C calls as a gap the hard stop can't cover, or the hard stop should move off the GIL (for example a `signal.alarm`/`setitimer` backstop, or a watchdog that isn't Python).
