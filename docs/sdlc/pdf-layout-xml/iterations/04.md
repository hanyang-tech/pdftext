## Requirements and design
Release (`release/security.md` #1, reproduced by the driver) found that `max_stream_bytes` bounds FlateDecode only: pdfminer decodes RunLengthDecode and LZWDecode outside the zlib shim, so SEC-1 holds only for Flate. Threat row 1 names zlib as the only route, so the fix needs a mitigation the design doesn't have. It goes to the architect as a delta (backlog #44, `must`), together with the default's sizing (backlog #45, `release/security.md` #2 and the second design issue), since both set the same bound.

Architect (general-purpose, opus), 06:53Z–07:31Z, report `04/architect-delta.md` (contract check passed, 0 send-backs; all ten `design.md` sections present). `DESIGN: READY`. It found the gap wider than the finding: every non-Flate filter, both predictors and Flate's own corrupt-data retry escape the limit, and CCITTFax costs 13 to 67 times its output. Proposal: nine bounded decode filters replacing the one zlib shim; `max_stream_bytes` from 256 to 32 MiB; CCITTFax refused under a limit; content-parser amplification accepted as threat row 4's fatal stop; SEC-1 and SEC-19 reworded to name the routes. Design gate: the user accepted all four recommended answers (32 MiB default; CCITTFax refused under a limit; parser amplification accepted, backlog #60; SEC-1 and SEC-19 reworded as proposed). Applied to `requirements.md`; the driver changed `design.md` C3 to "bounded decode filters". `README.md`'s `--max-stream-bytes` row (256 → 32 MiB) is edited at Integrate.
