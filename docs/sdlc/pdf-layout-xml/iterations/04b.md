Backlog #46 and #22. The script was added at Release at the user's request and has no criterion in `requirements.md`; the behaviour below is its spec for this lane.
- **Script behaviour (the spec, from `release/final-review.md` #3, U1, U5 and `release/security.md` #3, #4):**
  1. The script's exit code is the most severe pdftext exit code seen, ranked 1 > 2 > 3 > 0 (write failure or internal error, then refused or run stopped, then page errors, then ok). Any other non-zero code from the command counts as 1.
  2. `-h` and `--help` print the usage and exit 0. No arguments prints the usage to stderr and exits 2.
  3. In folder mode, two PDFs whose output folders would be the same (for example `x.pdf` and `x.PDF`, matched case-insensitively) never write to one folder: the second is not converted, a line says why, and it counts as refused (2). In single-file mode the given or default folder is used as now.
  4. Every file name the script prints has control characters (C0, DEL, C1) replaced, so a crafted name can't send terminal escape sequences. The name passed to pdftext is unchanged.
  5. `-o` or `--output` among the options passed through is rejected with a usage error (exit 2) before anything runs, since the script sets the output folder itself.
  6. A refused file leaves no empty output folder behind (as now); an output folder that held files before isn't removed.
  7. An empty folder, or one with no `.pdf` files, prints a message to stderr and exits 2 (as now).
- **README (`release/final-review.md` #1):** the `--page-timeout` and `--max-stream-bytes` rows say that usually the page becomes an error page (exit 3), but if the limit is hit while opening the file or reading the document structure, the run stops (exit 2). The "exits with the worst exit code" sentence says how codes are ranked.
